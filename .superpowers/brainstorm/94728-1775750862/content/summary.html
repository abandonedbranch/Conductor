WebReaderTool — Design Summary

Review the complete design before we write the spec

Scope
  • 4th gateway tool alongside Library, Manual, Action
  • Load user-provided HTTPS URL
  • Extract text via fixed JS: innerText
  • Return text to chat context
  • Apple SDKs only (WebKit)
Architecture
  • WebReaderTool — gateway entry point
  • WebReaderService — actor, owns extraction
  • WebReaderState — @Observable bridge
  • WebReaderError — structured Swift errors
  • WebReaderHost — WKWebView representable
Error Pattern
  • Tool throws structured Swift errors
  • Conductor reads error, decides response
  • No hardcoded user-facing strings in tool
  • Cases: invalidURL, insecureURL, navigationFailed, timeout, emptyContent, extractionFailed
Constraints
  • HTTPS only — HTTP rejected as insecure
  • No generated JavaScript — all scripts static
  • No SPA/lazy-load provisions
  • No Vision OCR (future iteration)
  • No retry logic — fail and inform
  • iOS 17+, iPadOS 17+, macOS 14+
UX
Transient loading card appears while page loads. WKWebView is mounted in view hierarchy but not user-visible. Card dismisses on success or transitions to error state on failure. Extracted text flows into chat context for the user to work with.
